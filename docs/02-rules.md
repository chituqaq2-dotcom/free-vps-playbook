# 02 · 硬规则（用户明确定下的）

1. **只白嫖**：永不绑卡、不付款、不升级、不选付费附加项。Oracle 只用 Always Free。
   - Oracle A1 Always Free 现在是总共 **2 OCPU / 12 GB**（不是旧的 4/24），永远不要配超过。
   - 例外只能由用户逐项明确批准，并写清边界。实例：用户曾批准某云“仅为更容易抢到配额而升级按量付费，仍只用免费资源，先设 $1 预算告警，绑卡由用户自己做”。Agent 遇到要输入新卡的页面一律停手交给用户。
   - 积分/代币类平台：免费送的积分也别花在“解锁地点”等付费项上，除非用户点头；不用促销码。
2. **账号**：只有用户明确要求才注册；默认邮箱注册，用户指定时可用 Google 等 OAuth（例如密码长度要求太苛刻时）；验证码/手机确认找用户。
   - **个人信息先问**：注册或填表要用真名、地址、电话等个人信息时，先告诉用户要填什么并等确认。用户说“随便起一个”就用化名。
   - **实名审核（KYC）表不替用户编造身份**：要“信息属实”的表，只填用户确认过的真实最小信息（例如城市级地址），或让用户自己填。
3. **机器用途**：只跑用户批准的节点和探针，不顺手装别的代理/面板。sing-box 没让动就别动。
4. **密钥**：任何密码、令牌、UUID、REALITY 私钥、隧道 token、探针 secret、订阅密钥都不出现在聊天里。
5. **排队/开通/没库存的免费机**：不用问，自己每 30 分钟检查一次，最多 10 次；成功后直接搭节点进订阅，再汇报。
6. **订阅**：改共享订阅 Worker 前先备份当前版本；新节点放在 DIRECT 之前，并加入「⚡自动选择」。
7. **独立订阅**：用户自己的主力订阅（例如 AWS 那条）保持独立，不合并、不改链接。
8. **命名**：`<VPS商>-<地区中文> | <流量限额 / 不限 / N天续期> | <电信延迟> | <速度>`，住宅 IP 加「家宽」。
9. **REALITY + Clash**：Clash/mihomo 输出必须带 `support-x25519mlkem768: true`。
10. **定时任务**：新建/修改/取消前先列出现有任务；不要建重复任务。
11. **服务条款**：明确禁止代理的平台（会封号的），先告诉用户风险，用户不点头不做。推荐/注册任何新平台前先做四项核实（见 [09 篇第 1 节](09-lessons-2026-11-27.md)）。
    - 绑在用户付费主账号上的“附赠云 VM”（如 AI IDE 的远程开发机）不要拿来搭代理：违规时可能连累整个主账号（邮箱、网盘一起没）。
12. **续期类机器**：到期前要么自动点续期，要么提前一天提醒用户；绝不让它静默过期。
13. **文档同步**：任何机器有变动（新增/删除节点、换 IP 或端口、换域名/隧道、改订阅、探针 id 变化、续期规则或到期日变化、新踩的坑），做完后**顺手同步两个仓库，不用问**：
    - 私密仓库 `HANDOFF_PRIVATE.md`：更新总览表、关键入口、待办与到期、对应机器的附录笔记。
    - 公开仓库（本仓库）：只写通用经验——新配方、新模板（先脱敏）、平台笔记、新踩的坑；绝不写入任何主机、域名、账号、密钥。
    - 提交信息写清改了什么（如 `node: add XX-JP东京` / `pitfall: XX 面板重启后需手动拉起`），推送后在汇报里一句话带过。
