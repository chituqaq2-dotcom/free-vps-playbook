# 08 · 接手清单（新 Agent 第一天）

1. 读完本仓库，再读用户私下提供的 `HANDOFF_PRIVATE.md`（先看顶部的“当前状态总览”，它比后面的历史附录新）。
   - 上一个 Agent 的本地文件、脚本、密钥**通常不会跟过来**。附录里的本地路径多半已不存在；第一件事是核对哪些凭据真的在你的保险库里，缺什么列给用户。
2. 请用户把私密值存进你的保险库/密钥管理（不要贴在聊天里）：面板登录、root 密码、CF token、GitHub PAT、探针 secret、订阅密钥。
3. 巡检一次，只汇报红灯：
   - 探针：每台 `last_active`。
   - 订阅：base64 能解出几行、Clash 有几个节点、自动选择组是否完整。
   - Actions：最近一次运行是否成功；kick Worker cron 是否还在。
   - 定时任务：续期提醒/自动点击是否都在且日期正确。
4. 把即将到期的事（续期、试用取消）排进你自己的定时任务。
5. 有不确定的规则，按"更保守、更常问"的读法执行，直到用户确认。

## 之后的日常
- 每次机器有变动，按 [02-rules 第 13 条](02-rules.md) 同步私密仓库和本仓库，不用等用户提醒。
- 推送前全仓库搜一遍域名、IP、UUID、token 形状的长串，确认公开仓库里没有私密信息。
- 私密仓库也一样：可以写主机名、IP、保险库条目 id、文件路径，但**不写**密码、节点 UUID、REALITY 私钥、token、订阅路径密钥。订阅链接写成 `https://sub.<域名>/<KEY>`。
- 每次大改后在私密交接顶部更新一份“当前状态总览”：每台机器（平台、位置、访问方式指针、协议端口、探针 id、续期规则和下个截止日、在哪个订阅）、全部定时任务 id、等用户拍板的事、待轮换的密钥。
