# 10 · 2026-11-25～26 经验汇总（脱敏）

## 1. 接手
- 交接时上一个 Agent 的本地文件与密钥没过来，订阅改不了、探针后台进不去。先请用户把 CF token、探针后台登录存进保险库，再把订阅 Worker 源码拉回本地并做一份“接手备份”。
- CF token 的 verify 接口可能返回 Invalid，但实际 Workers/KV/Tunnel API 能用；以真实调用为准。
- 用户在聊天里贴过的密钥，事后记进“待轮换”清单。

## 2. 宿主宕机的处理顺序
1. 先看平台官方状态页/公告：宿主节点被标 Outage 时，面板 Start、终端多半都灰着，等它恢复最省事。
2. 用户不急用时就等，别急着删机；用户批准了才删机重抽/迁移，并把“换地址要改订阅”说清楚。
3. 迁移（Emergency recovery 类）往往要求事先有备份/快照、且别的节点有空位——**上线后就先做一次备份**。
4. 删机重抽时避开已知坏节点（看论坛反馈），抽到坏的就再抽，设上限次数。
5. 宿主恢复后进程是否自启要用探针确认，别信浏览器的“已恢复”。

## 3. 链式落地（静态/住宅 SOCKS5）
- 详见 03 篇 D 节。要点：国内直连 socks5 会被墙 → Clash `dialer-proxy` 经加密前置；base64 版放不了；前置以用户本地实测为准，用户侧超时就换一条。
- 纯净度：同一个 IP 在不同库里可能一个说商宽 risk 0、一个说机房+代理；论坛帖子的综合打分又是第三种口径。如实告诉用户“不保证是家宽”，命名时别写死“家宽”，或写明来源。

## 4. 平台反代与休眠
- 只给 HTTP 口的 PaaS：先测平台是否流式转发。实测某平台把下行整段缓冲 10 秒以上，XHTTP/WS 代理零流量，加关缓存头无效，最终删项目。
- “后台应用”模式+出站隧道理论上能绕开休眠，但若条款明禁代理/隧道且有自动扫描，直接放弃，账号留着、定期看条款是否放宽。

## 5. 赠金类服务与个人信息
- 注册赠金类服务前先问用户用什么名字/邮箱；KYC 问卷先把题目拿给用户看。
- 不要替用户提交编造的身份信息；可以用用户确认过的城市级地址等最小真实信息。

## 6. 用户手机注册海外账号（顺带的咨询）
- 地区主要看注册时的 IP，但手机插国内 SIM 会被判成中国；建议拔卡或用电脑、全局走目标国家出口、生日填成年。
- 判错区后走官方国家/地区关联表单申请改区，一两天回邮件；期间只用同一国家的出口登录。
- 家宽池会自动换城市，但同国内换城市一般无碍；关键是别出这个国家。

## 7. Agent 额度
- 一天的 Agent 额度快用完时，用户可能让重活顺延到次日某个时刻。用一次性定时任务承接，任务里写全方案和规则，因为执行时没有当时的对话上下文。
